# Non-publishing boundary

Current lightweight tasks allow W to select an image host and upload only the article's intended-public images, obtain direct public URLs and build complete HTML/Markdown pages. See [image hosting](../skills/blog-writer/references/image-hosting.md). This exception does not authorize blog-editor writes, media uploads to the target blog platform, drafts, publication, payment or unapproved account creation. The remaining indexed-workspace rules below are historical compatibility guidance.

This matrix excludes content-release writes: article editor input, draft creation, article-media uploads, scheduling, publishing, deletion, rollback, publishing API writes and browser fingerprint management. Its sole release profile remains human-native. Before writing, [account preparation](account-preparation.md) is a separate owner-authorized exception for specified registration/login, necessary verification/profile fields and default-only publishing-space creation. The exception does not permit tests, article writes or arbitrary site building. Without that specific authorization, authentication and setup remain human actions. `release_policy.machine_external_writes_allowed = false` refers to the content-release layer and must not be enabled to prepare an account.

The sole release-facing artifact is a local, visual rich-text hand-off. Before W/R dispatch, each current-schema article must already have an owner-confirmed distinct platform/account assignment and compatible locale row. A human can paste the handoff into that platform’s native fields, replace image cards and inspect the public reader page. They do not edit platform HTML/DOM to force heading tags. After humans record URL/state in structured return receipts, the registered campaign G may make one bounded read-only batch HTTP/browser observation and contract check with a separate evidence row per article. It accepts title hierarchy only from rendered public visual evidence, not local, editor, source or snapshot markup. It does not operate the platform, create a fresh public-QA agent, or restart W/R. A transport repair returns to the human and then the same G's next batch recheck; only an explicit owner-requested canonical/payload change can re-enter that article's W–R path. If an organization later builds a platform adapter, it must live in a separate repository and be separately authorized; it cannot alter this matrix’s W–R–G decisions or platform scope.
