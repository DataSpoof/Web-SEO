# 双线外链挖掘矩阵

[English](README.md) · 简体中文 · 版本 1.1.1 · [MIT 许可证](../../licenses/backlink_skills-LICENSE)

这是一个面向 Codex 的开源外链研究 Skill 套件。它把“大规模候选发现”和“高质量文章投稿”分成两条独立筛选线，再通过统一的源表、去重、批次和工作簿规则完成交付。

本矩阵解决候选获取、压缩、筛选、去重和制表问题。它不是自动群发工具，也不承诺收录、链接属性、流量或排名。

## 两条线路

| 线路 | 主要目标 | 筛选方式 |
|---|---|---|
| 批量提交线 | 尽可能扩大合法、相关、可执行的产品收录候选 | 条件宽松，允许登录、验证码、人工审核和 `nofollow`；排除正式文章、强制回链、强制徽章和明确删除风险 |
| 质量投稿线 | 寻找值得投入内容和沟通成本的编辑型机会 | 综合主题适配、准入难度和预期回报；费用不明不能视为免费 |

## Skill 矩阵

| Skill | 职责 | 主要产物 |
|---|---|---|
| `backlink-expansion-matrix` | 冻结范围、路由阶段、检查交接和验收状态 | 项目路线、阶段边界、验收结论 |
| `backlink-source-prep` | 整理自然搜索竞品、反向链接差异、引荐域名和公开清单 | 源文件登记、合并候选、排除表、优先候选、统计报告 |
| `backlink-batch-expansion` | 筛选工具目录、产品导航、创业项目库、社区资料页和资源推荐页 | 批量线可执行池、备用池、排除表 |
| `backlink-quality-expansion` | 筛选文章投稿、行业媒体、专家贡献和编辑型资源页 | 质量线免费候选、付费或待确认候选、排除表 |
| `backlink-workbook-delivery` | 历史去重、跨线路去重、批次冻结、制表和质量检查 | 免费/付费工作簿、去重记录、质量检查报告 |

## 工作流

```text
目标品牌与交付要求
        │
        ▼
自然搜索竞品与其他参考来源
        │
        ▼
竞品反向链接差异／引荐域名／历史表／公开资源
        │
        ▼
标准化、合并、排除噪声、生成优先候选
        │
        ├───────────────┐
        ▼               ▼
批量提交线          质量投稿线
        │               │
        └───────┬───────┘
                ▼
      历史去重与跨线路去重
                │
                ▼
      免费／付费执行工作簿
```

## 为什么要先压缩再筛选

反向链接导出通常包含重复引荐域名、重复的“目标网站—引荐域名”组合、无关站群，以及指向同一投递入口的多个网址。因此应先统一格式、合并重复项，再安排站点级筛选。本仓库不包含任何真实品牌清单、业务数据、账号信息、历史投递记录或项目专用门槛。

## 安装

在仓库根目录执行：

```sh
cp -R 双线外链挖掘矩阵/skills/* ~/.codex/skills/
```

安装后可以直接调用：

```text
$backlink-expansion-matrix
$backlink-source-prep
$backlink-batch-expansion
$backlink-quality-expansion
$backlink-workbook-delivery
```

## 完整使用教程

### 第 0 步：先冻结任务范围

开始前向 Codex 提供以下信息：

- 目标品牌名称和规范官网；
- 本次处理批量线、质量线，还是两条线都做；
- 已有候选表、历史已投表和已经导出的批次；
- “补足到 N 条”还是“新建 N 条”；
- 每批数量；
- 是否允许使用浏览器导出 Semrush；
- 是否明确允许子代理并行；
- 最终工作簿列名和输出位置。

“已有 A 条，补足到 B 条”只新增 `B-A` 条，不能被解释为再做 B 条。

推荐启动指令：

```text
使用 $backlink-expansion-matrix 启动双线外链扩量。
目标品牌为……；批量线补足到……条；质量线补足到……条；
历史已投表位于……；最终每个工作簿分为免费和付费两个工作表。
先冻结范围并告诉我缺少什么，不要执行真实投递。
```

### 第 1 步：建立工作区

建议至少分成以下目录：

```text
workspace/
├── 01-源表材料/
│   ├── 自然搜索竞品/
│   ├── Semrush反向链接差异原始数据/
│   ├── 历史候选表/
│   └── 历史已投表/
├── 02-候选池/
│   ├── 批量线/
│   └── 质量线/
├── 03-扩量表交付物/
└── 04-流程与校验/
```

原始文件只复制和登记，不覆盖。中间表、排除表、质量检查报告和最终工作簿分开保存。

### 第 2 步：获取自然搜索竞品

对每个目标网站从 Semrush 导出自然搜索竞争对手完整表。选择参考竞品时一起看：

- 竞争相关度；
- 共同关键词；
- 自然关键词和估算自然流量；
- 产品主题是否相近；
- 对方外链是否可能对目标品牌有参考价值。

不要把整个项目限制在单次比较批次中。应先建立较大的参考竞品池，再根据当前产品界面支持的比较槽位分批分析。

### 第 3 步：分批导出反向链接差异

每批数量按当前产品界面支持的比较槽位确定。每批记录目标域名、竞品、批次号和导出日期，推荐命名：

```text
差异-目标域-第01批-YYYY-MM-DD.csv
差异-目标域-第02批-YYYY-MM-DD.csv
```

浏览器操作时注意：

- 只使用用户授权的账号和浏览器会话；
- 不访问无关页面，不修改账号、安全或订阅设置；
- 遇到验证码或安全验证时停止，不绕过；
- 每导出一批就登记，避免漏批和重批。

自然搜索竞品与竞品反向链接是两个独立来源：前者回答“谁值得参考”，后者回答“这些竞品从哪里获得链接”。

### 第 4 步：盘点原始导出

运行源表审计脚本：

```sh
python3 skills/backlink-source-prep/scripts/audit_semrush_exports.py \
  --input-dir /path/to/semrush-exports \
  --report /path/to/source-audit.json
```

该脚本只盘点 CSV 文件数、非空行数、空表、读取错误和表头差异。它不会自动判断某个域名是不是可投递平台，也不会替你完成业务筛选。

### 第 5 步：合并和压缩源数据

调用源表技能：

```text
使用 $backlink-source-prep 读取这些 Semrush 导出。
保留原始文件和来源字段，统一域名，输出合并候选、排除表、优先候选和统计报告。
不要把候选来源写成已核验平台。
```

压缩顺序建议为：

1. 删除空值和无法解析的记录；
2. 合并相同的“目标网站—引荐域名”组合；
3. 标记目标自身域和竞品自身域；
4. 排除明显短链、博彩、恶意、镜像和垃圾域名；
5. 计算目标覆盖、竞品覆盖和跨目标唯一域名；
6. 用覆盖度、链接实力、流量和主题信号安排检查优先级。

文件名应带数据量，例如：

```text
反向链接差异原始数据-<行数>条-<文件数>份/
合并去重候选-<行数>条.csv
优先候选-<行数>条.csv
排除数据-<行数>条.csv
```

高权重通用网站不自动等于可提交平台，小型垂直目录也不应仅因权重低而删除。

### 第 6 步：筛选批量提交线

调用：

```text
使用 $backlink-batch-expansion 从优先候选中扩充批量提交线。
扩量优先，允许注册、登录、验证码、人工审核和 nofollow；
排除必须发布正式文章、强制回链、强制徽章和存在明确删除风险的平台。
输出可执行池、备用池和排除表，不制作最终工作簿。
```

没有找到明确入口但仍有参考价值的网站进入备用池，不要伪造 `/submit` 地址。同一域名可以保留不同的真实提交对象，例如工具收录和创业项目收录，但最终指向同一表单时只保留一个。

候选池完成后运行：

```sh
python3 skills/backlink-batch-expansion/scripts/validate_candidate_pool.py \
  --input /path/to/candidate-pool.csv \
  --report /path/to/candidate-pool-qa.json
```

### 第 7 步：筛选质量投稿线

调用：

```text
使用 $backlink-quality-expansion 扩充质量投稿线。
分别判断主题适配、准入难度和预期回报；
优先使用官方投稿指南和编辑政策作为证据；
输出免费候选、明确付费或费用待确认候选、备用池和排除表。
不要写文章、联系编辑或付款。
```

同一媒体同时存在免费编辑投稿和付费品牌内容时，可以保留两个入口，但条件、费用和 URL 必须分开。费用未说明不能归入免费。

### 第 8 步：历史去重和批次冻结

调用：

```text
使用 $backlink-workbook-delivery 对两条线路执行历史去重、跨线路去重和已导出批次去重。
历史表没有品牌字段时，明确说明只能做平台级去重，不能声称某个品牌已经投过。
已导出的批次必须冻结。
```

去重分为三层：

1. 标准 URL 去重；
2. 同一平台域名下的入口判断；
3. 历史已投、旧批次和当前两条线路交叉检查。

相同入口不能同时出现在批量线和质量线。工具提交入口与编辑投稿入口确实不同时，可以分别保留。

### 第 9 步：制作执行工作簿

默认每条线路一个工作簿，每个工作簿包含“免费”和“付费”两个工作表。可见列为：

```text
域名 | URL | 投递条件 | 适合品牌网站
```

明确免费进入免费表；明确收费进入付费表；费用待确认进入付费表，并在投递条件中写明“费用待确认”。来源、证据、状态和内部编号留在内部候选库。

生成工作簿前先校验导出 CSV：

```sh
python3 skills/backlink-workbook-delivery/scripts/validate_delivery_csv.py \
  --input /path/to/delivery.csv \
  --report /path/to/delivery-qa.json
```

生成 XLSX 后必须重新导入检查工作表、列名、数据行和公式错误，并查看每张表的顶部、底部和新增区域。视觉检查不能替代数据检查。

### 第 10 步：执行反馈和下一批

第一批开始真实提交后，先按用户确认的抽样数量收集反馈，记录：

- 入口是否仍有效；
- 实际免费还是付费；
- 是否需要登录或验证码；
- 是否强制回链或徽章；
- 是否适合对应品牌；
- 已提交、等待审核、已公开、被拒绝或结果未知。

若入口失效率、强制付费率或品牌不匹配率明显升高，先调整排序和筛选规则，再生成下一批。候选数、实际提交数和公开收录数必须分别统计。

## 常用调用方式

### 只整理源表

```text
使用 $backlink-source-prep 盘点并整理这些导出，只交付源文件登记、合并候选、排除表、优先候选和统计报告；不要进入站点筛选。
```

### 补足批量线

```text
使用 $backlink-batch-expansion 将现有批量表从 A 条补足到 B 条，只新增 B-A 条，并保留原批次关系。
```

### 新建质量线批次

```text
使用 $backlink-quality-expansion 新建 N 条质量投稿候选，综合主题适配、准入难度和预期回报，费用不明不得放入免费组。
```

### 只做去重和制表

```text
使用 $backlink-workbook-delivery 读取已筛候选和历史已投表，只做去重、批次冻结、免费/付费分表和质量检查，不重新研究网站。
```

## 验收清单

- 原始文件没有被覆盖；
- 每条候选能追溯到来源；
- 批量线和质量线没有套用同一筛选门槛；
- 费用待确认没有被写成免费；
- 标准 URL、平台域名、历史表和旧批次均已查重；
- 已导出批次没有重新分配；
- 工作簿只有用户要求的可见列；
- 工作簿已重新导入并完成视觉检查；
- 交付物明确标为“待执行候选”；
- 没有把页面可访问、表单存在或 HTTP 200 写成已提交或已收录。

## 数据和执行边界

- 仓库只包含通用工作流、规则、模板和校验脚本，不包含任何专有品牌配置、业务数据、项目统计、历史投递记录或账号信息。
- Semrush、竞品外链和公开清单只是候选来源，不证明站点可投递。
- 未经明确授权，Skill 不注册、不登录、不付款、不提交，也不联系站方。
- 验证码和安全验证必须由网站原生流程或用户完成，不得绕过。
