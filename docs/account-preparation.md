# 账号准备：注册、登录与最低必要设置

目的：在正式写作前尽早发现账号障碍，减少白写；不是提前证明文章一定获准发布。只读平台调研先判断读者、语言、政策和品牌要求，账号可用不能替代这些判断。

## 何时执行与谁负责

只读匹配 → 用户授权具体平台与拟用身份 → 账号准备 → 汇入完整写前方案 → 用户确认 → W 成稿与载荷 → 独立 R → G 验收 → 人工发布。启动时已有足够明确的批量授权就复用，不逐站重复询问；候选清单、密码或内部匹配提案本身不是操作授权。账号准备授权不等于最终平台/文章映射确认，不得据此改 `allowed_pairs`。

G 负责收齐资料、保存授权和汇总；复用一个可见 `CAMPAIGN_OPERATIONS_STEWARD` 依次处理本批账号，单个平台短检查可由 G 执行。不按平台新建代理。匹配子角色仍只读；W/R 不参与账号操作、不接收凭据。确认前允许这项有界服务，但仍不得创建文章路径、派 W/R 或写稿。

## 授权与资料一次收齐

由 G 将用户的非敏感授权原文与来源保存在 `evidence/owner-confirmations/`，候选原始资料保存在 `evidence/owner-selection/`。只为真正要准备的目标建立[授权记录](../templates/account-preparation-authorization.json)，保存路径、哈希、具体平台、账号安全标签、允许动作和指定浏览器。账号标签可由 G 根据已明确身份生成，不要求用户额外发明别名；邮箱/凭据指向安全来源，不把安全标签当成账号已验证。

基本资料复用一份品牌资料卡：品牌名、作者展示名、简介、官网、现成头像、用户名/博客地址首选及允许变体。关系按本任务用户已声明的 `founder` 处理，不据此编造机构账号、真实身份或权限。没有现成头像时可保留默认；缺身份材料或必要命名决定集中询问，不猜地址、年龄、法律主体或被占用名称的替代方案。

可以一次授权：“允许在指定平台用已提供身份注册/登录，并以现成资料创建必要博客或频道，采用默认主题和布局；不付费、不装修、不发布测试内容。”创建账号可能产生公开作者页，创建博客/频道可能产生公开站点，须在授权中讲清楚。只授权登录就不能注册；只授权注册不能顺手建博客；访问邮箱、验证邮件和创建发布空间分别明确。未授权备选不提前注册。

操作前运行一次目标授权校验：

```sh
python3 skills/blog-harness/scripts/check_account_preparation.py \
  --workspace /absolute/campaign-root \
  --manifest evidence/operations/account-preparation-authorization.json \
  --target-id ACCOUNT-01
```

该工具只检查本地来源/授权哈希、目标范围及动作白名单，不启动浏览器，不证明原文语义已获授权、账号可用或发文成功。G 必须先确认原文确实授权了列出的身份和动作；内部 JSON、工具通过或本技能的安装均不能代替用户授权。授权内容改变后才重新校验，不为每个点击运行一次。

## 设置做到哪里就停

| 类型 | 做法 |
| --- | --- |
| 注册和必要验证后直接发文 | 优先考虑；已有有效会话不退出重登。 |
| 简单设置后发文 | 在明确授权下填博客/频道名、可用地址、必要简介及资料，保留默认主题、布局和可选设置；必要头像仅用用户提供且授权的现成资产。 |
| 需要额外建设或资格 | 默认不继续：专门生图、装修、栏目/导航/多页面、域名/DNS/代码、导入联系人/邀请成员、订阅试用/付款、申请投稿资格或等待审批。记录并交用户决定，不为沉没成本继续。 |

不按步骤数、平台名字或“能建 Blog”判定成本。所需资料已具备、路径清楚、接受默认设置、无需额外技术调查，且完成后可到目标发文入口，才属于简单设置。品牌展示、实际文章入口、人工成本与受众一起权衡；简单博客可优于不适配的直发平台，不承诺收录或链接收益。

允许检查身份、目标博客/频道和后台明确展示的权限、发文入口、封禁/付费/审核提示。按钮可见只是入口证据，不等于有发布权限。默认不打开可能自动创建草稿的编辑器，不输入测试内容，不上传文章图片、不保存/发布/调度、不修改/删除已有内容。不能通过 API、DOM 修改或发布测试文章绕过人工发布边界。

## 浏览器、凭据与停止条件

- 优先已有授权会话或用户密码管理器填入；必要时只从用户授权的安全来源使用凭据，只交官方注册/登录页面。不在任务提示、配置、报告、命令参数、仓库或截图中保存密码、Cookie、令牌、验证码；只传引用。不宣称工具记录天然保密，没有安全输入方式就由用户填入再继续。
- 指定指纹浏览器时严格使用指定配置/内核，不替换普通浏览器、不修改指纹客户端。只保留必要标签页，同一浏览器串行操作；崩溃时在不改客户端配置的前提下重新打开指定浏览器，身份或安全恢复路径不明则停。
- 验证邮件仅在指定邮箱访问明确授权后处理，不读取无关邮件；CAPTCHA、2FA、身份核验交用户完成，不绕过。授权范围外的 OAuth 权限、付费或安全设置变更立即停。
- 密码错误、封禁或资格障碍不反复试；普通网络异常仅作有依据的有限恢复。没有新依据就停止技术试错。等待用户/验证邮件时保存准确恢复点，不持续刷新、轮询；一处受阻继续其他已授权账号。不自动换邮箱、重注册、删账号或改平台。

## 汇报与继续条件

只维护一份批量结果表 `evidence/operations/account-preparation-results.md`，逐行记录目标 ID、平台/安全账号标签、时间、身份/验证结果、发布空间和权限证据、品牌显示、障碍、恢复入口与下一步。只留必要脱敏证据，不复制账号页面全文，不将私有后台信息纳入公开包。

结论用“具备开始写作的账号条件／需要补准备／需要用户决定／没有查明”。注册成功、登录成功、入口可见、权限已验证分别记录；不使用 `PUBLISHED`、`PUBLIC_QA_PASSED` 或无条件“可发布”。图片、链接、内容审核和公开视觉仍未实测。

结果引用进原 `task_and_audience` / `risks_and_owner_decisions`，不另做平台审批或审稿。尚未就绪的文章不默认启动；用户可以在完整方案中明确接受其账号风险、先做本地内容，G 记录该选择而不伪造就绪。整批写前方案仍先确认，确认后已就绪文章继续、受阻文章单独等待。候选不足不缩量、不复用平台或扩范围；停下的已注册账号保留，不擅自删除。

机器投影沿用已有字段：`evidence_refs` 指向授权及批量结果表，`risks_and_owner_decisions` 写明具体未决账号问题和用户允许先做本地内容的原文来源；最终回执仍由 `confirm-prewrite-plan` 绑定。不新增账号评分或整批派发门。`dispatch-readiness` 校验的是映射、受众及写前确认，不评估账号实况，`DISPATCH_READY` 不能代替 G 对本篇就绪/风险选择的检查。接受账号风险不能豁免受众、CTA 或其他已确认需求。

账号准备记录绑定具体账号、发布空间和时间，不作为永久平台能力。会话过期只需恢复授权登录，不重做匹配、注册或整轮核验；账号/空间/权限发生变化时才补查。现有历史项目不自动新增这一环节。
