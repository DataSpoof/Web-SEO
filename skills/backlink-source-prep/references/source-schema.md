# 源表字段和压缩规则

## 标准源表字段

| 字段 | 含义 |
|---|---|
| source_file | 原始文件名 |
| report_type | 自然竞品、反向链接差异、引荐域名、历史表或公开清单 |
| target_domain | 目标品牌域名 |
| source_competitor | 提供线索的竞品域名 |
| referring_domain_raw | 原始引荐域名 |
| root_domain | 标准化根域名 |
| source_url | 原始来源 URL，可空 |
| target_coverage | 覆盖的目标网站数量 |
| competitor_coverage | 覆盖的竞品数量 |
| authority_signal | 来源工具提供的链接实力信号 |
| traffic_signal | 来源工具提供的流量信号 |
| exclusion_reason | 被排除时的具体原因 |
| source_status | 原始、可用、排除、优先候选 |

## 标准化

域名转小写，去除协议、`www.`、端口、结尾点和明显追踪部分。必须保留原始值，便于追溯。根域名计算若涉及多级公共后缀，应使用可靠解析库或保守保留主机名，不能简单截取最后两段后宣称准确。

## 分层压缩

1. 删除空值和无法解析的记录。
2. 合并完全相同的“目标域—引荐域”组合。
3. 标记而非静默删除自有域、竞品自身域和常见通用平台。
4. 对短链、镜像、赌博、恶意和垃圾特征给出排除原因。
5. 计算跨目标唯一域名和覆盖度。
6. 根据覆盖、链接实力、流量和主题信号生成优先候选。

压缩只降低后续检查成本，不等于完成平台有效性核验。
