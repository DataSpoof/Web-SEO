# 图片公开地址与完整图文发布页

W 选择图床、上传本篇可公开的最终图片，取得每张正文图及独立封面的公开直链。随后生成完整 HTML 和 Markdown 发布页，R 审最终页面及实际图片。

## 选择与上传

- 优先复用项目已授权、可用的图床或对象存储；否则选择允许公开嵌入、保留期适合文章用途、支持 PNG/JPG 的服务。选择时核对官方说明和当前能力，不固定品牌，不用短期临时存储。
- 本能力允许上传本篇计划公开的图片到图床。只上传最终素材，保留本地编号文件；正文、凭据、私有截图和其他文件不在上传范围内。
- 复用可用的官方 API、CLI 或上传工具，必要时用浏览器。已有授权凭据仅由安全机制读取，不写进稿件、地址、日志或交给 R。需要新账号、额外权限、付款或素材公开权限不明确时，向用户说明。
- 同一文件已有可用地址时复用。图片改动后上传新版本并更新地址，避免缓存继续显示旧图。

## 记录与核验

在作者 Markdown 信息块的每张 `images` 和 `cover` 记录中，增加 `public_url`，保留原 `file`、Alt 和图注。例如：

```json
{"file":"images/01-lead-topic.png","public_url":"https://your-public-image-host.example/01-lead-topic.png","alt":"文章语言的图片说明","caption":"文章语言的图注"}
```

使用真实上传结果替换示例；分享页、登录页、本地地址和带临时签名的链接都不是图片直链。匿名访问应直接返回对应 PNG/JPG，图片与最终本地素材一致，并能在发布页中实际显示。核验一次后复用记录，地址或文件改变才重新核验：

```sh
python "${CLAUDE_PLUGIN_ROOT}/skills/blog-writer/scripts/build_release.py" --plan /项目/task-plan.json --article-id A01 --verify-images
python "${CLAUDE_PLUGIN_ROOT}/skills/blog-writer/scripts/build_release.py" --plan /项目/task-plan.json --article-id A01 --check
```

第一条匿名 GET 图片，核对响应类型及文件内容，并生成两种发布页；上传由模型使用图床工具完成。第二条离线检查当前稿、URL、素材与页面是否一致。核验信息存于已有 `handoff/.build.json`。防盗链、有效期和删除风险在原交付说明中简短记录。

## 两种发布页

HTML 在正文准确位置显示真实图片并写入 Alt 属性；Markdown 在同一位置使用 `![Alt](<公开URL>)`。两份都包含完整全文、图片和读者图注，正文不插入中文操作卡、文件名或上传说明。正文之后是 SEO 信息和摘要，独立封面与图片资料单列，资料包含可见 Alt、图注、文件名和公开 URL。

公开图片 URL 是正式交付的默认要求，漏填配置也不会关闭，显式设为 false 也不能生成占位式正式交付。旧文件原样保留；重新交付按本次要求完成。没有可用图床时报告缺项并保留本地稿。

制图或上传尚未完成时，可加 `--local-preview` 生成 `preview/` 下的草稿，两份均标注草稿；它不写入正式 `handoff/`，下一步是完成公开图片。正式页仍用 `--verify-images` 生成，再用 `--check` 核对。

博客平台编辑器、保存草稿和发布仍由人工完成。复制后是否保留图片、平台是否重新托管图片，由人工发布后的 G 检查。
