# 总候选库字段与规则

## 建议内部字段

| 字段 | 用途 |
|---|---|
| record_id | 稳定唯一编号，不能因 URL 格式变化而改变 |
| root_domain | 标准根域名 |
| normalized_url | 标准提交入口 URL |
| line_type | 固定为“批量线”，用于与质量线分流 |
| entry_type | 工具提交、产品目录、创业项目、社区、资源页等 |
| condition | 执行人员需要知道的投递条件 |
| fee_status | 明确免费、明确付费、费用待确认 |
| suitable_brands | 一个或多个适合品牌 |
| source | Semrush、资源页、历史候选表等来源 |
| source_competitors | 提供该候选的竞品域名 |
| evidence_note | 入口和费用判断的简短依据 |
| pool | 可执行池、备用池 |
| status | 待检测、已找到入口、可进入批量表、已分配、已导出、已排除 |
| batch_id | 已冻结的批次编号 |
| execution_result | 执行人员回写的结果 |

最终执行工作簿不必暴露内部字段。只导出用户要求的执行列。

## URL 标准化

1. 域名转为小写，去除协议、`www.`、端口和结尾点。
2. URL 保留实际路径，删除明显的追踪参数和片段标识。
3. 统一结尾斜杠规则，但不要改变可能依赖路径的表单地址。
4. 解析跳转后的正式地址时保留原始来源，不能只保存跳转服务地址。
5. 从标准 URL 的主机名重新计算用于查重的域名。历史“域名”列只作为显示值，不能作为唯一查重依据。

## 查重

- 标准 URL 相同：直接重复。
- 同一根域名、不同 URL：判断是否为不同的真实提交方式。
- 不同页面最终指向同一表单：只保留一个。
- 工具提交和创业项目提交等对象不同、条件不同的入口可以同时保留。
- 已导出记录不能因重新排序进入新批次。

## 入口识别

优先检查首页、页脚、公开导航及少量常见路径，例如 `/submit`、`/add-tool`、`/get-listed`、`/submit-startup`、`/advertise`。出现登录、注册、验证码或审核要求仍可保留。

普通联系页、广告询价页、用户注册页不能仅凭页面名称直接当作提交入口。没有找到入口的高参考价值网站转入备用池，不直接删除。

## 状态变化

候选阶段推荐单向状态：

`待检测 → 已找到入口 → 可进入批量表 → 已分配批次 → 已导出`

只有首页、联系页或入口仍待确认的记录进入“备用池”，不能直接导出为可执行项。确认不符合规则时进入“已排除”。

导出后的执行状态单独记录：`待提交 → 已提交 → 收到回执 → 已公开 → 公开页已检查`，并允许 `已拒绝`、`入口失效`、`强制回链`、`费用不符` 等终止状态。不要用一个笼统的“已完成”混合这些阶段。

## 并行合并

- 为每个子代理分配互不重叠的来源或记录范围。
- 在分片登记表中记录 `shard_id`、代理、来源范围、输出文件、开始状态和完成状态。
- 子代理输出相同字段的独立 CSV。
- 主代理合并时重新执行一次标准化和全局查重。
- 只有主代理写总库、分配批次并导出最终工作簿。

## 批次冻结

批次大小是可配置参数。批次一旦导出，`batch_id` 和其记录集合必须冻结。改变批次大小、排序或筛选规则时，只处理未分配记录，避免执行人员的历史记录失去对应关系。

“补足到 N 条”和“新建 N 条批次”是两个不同操作。前者新增数为 `N - 现有有效记录数`；后者不把历史记录计入新批次。执行前必须按用户原话确定模式。
